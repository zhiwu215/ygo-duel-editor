# 卡库角色与文本覆盖合并

## 起因

KCG 的中文语言包（`config/languages/Chs/*.cdb`）有两个问题：

- 它的 `datas` 数值列不可信 —— `anime.cdb` 有 499 行 `ot=0`（其中 474 行真库是 `ot=16` 卡片力量）、2 行 `type=0`（`153999999 虚拟世界`、`153000000 卡组统领`，真库都是 `type=2` 魔法）。
- 但它的 `texts` 是唯一的中文卡名与效果文来源 —— 真库 `cdb/*.cdb` 的文本全是英文（`cards-unofficial.cdb` 5880 条里含汉字的 0 条）。

于是挂哪个库都得放弃一半：挂语言包 → 中文名齐全但 `ot`/`type` 是坏的（卡片力量少 220 张、个别卡显示「未知」）；挂真库 → 数据准确但中文关键词搜不到任何东西。

本次给项目加上「数据取真库、文本取语言包」的合并能力，两者兼得。

## 卡库角色

每个已加载的卡库有一个角色：

| 角色 | 含义 |
| --- | --- |
| `data` | 提供卡片数据（`ot` / `type` / 攻防…）与文本 |
| `text` | 只提供文本（卡名与效果文），即语言包 |

主库永远是 `data`。附加库的角色：**手动指定优先，未指定的自动识别**。

自动识别规则：加载完成后统计每个附加库的卡密集合，若**有 90% 以上已被其它已加载库覆盖**，就判定为 `text`（说明它只是叠加层，不是独立卡池）。

实测数据支撑这个阈值：

| 库 | 卡密数 | 与其它库重叠 | 判定 |
| --- | --- | --- | --- |
| `config/languages/Chs/anime.cdb` | 6161 | 5880（95.4%） | text |
| `cdb/cards-unofficial.cdb` | 5880 | 0 | data |
| `cdb/cards.cdb` | 14759 | 0 | data |
| `MyCardLibrary/ygopro/cards.cdb` | 15019 | 0 | data |

正经数据库之间是 0% 重叠，语言包是 95.4%，阈值取 90% 有足够余量。

## 合并规则

- `datas` 取**第一个**命中该卡密的库（数据连接排在文本连接前面）。
- `texts` 取**文本库**里的那一份；文本库没有该卡密时才退回数据来源库的文本。
- 只在文本库里存在的卡密（如 DM 系列的 `511000559~511000591`）仍然可见，用文本库自己的 `datas` 兜底。

实现方式：

- 文本库按顺序 `ATTACH` 到每个数据连接上（别名 `ov0`、`ov1`…），查询时文本字段用 `COALESCE(ov0.name, t.name)` / `COALESCE(ov0.desc, t.desc)`，因此**搜索也走合并后的文本**（中文关键词照样能命中）。
- 每个库都排除「前面已加载的库」已有的卡密 —— 建一张 `temp.__covered` 临时表装前面的卡密，`WHERE` 里加 `AND d.id NOT IN (SELECT id FROM __covered)`。这样同一个卡密只由第一个命中的库提供，`count(*)` 与列表一致，多数据源之间也不会重复计数。
- 只读连接上 `ATTACH` 与 `CREATE TEMP TABLE` 都可用（已实测），全程不写用户的 cdb 文件。

## 使用方式

1. 在设置里把真库加为附加卡库：`E:\Edopro-kcg\cdb\cards-unofficial.cdb`（想要 KCG 的扩展卡池再加 `config/languages/Chs/KCG.cdb`、`neet.cdb`）。
2. 语言包 `config/languages/Chs/anime.cdb` 会自动识别为「仅文本」；若没识别出来，手动把「用途」改成「仅文本（语言包）」。

注意：**只把真库追加到列表末尾、不挂语言包的话，拿到的仍然是英文卡名** —— 中文来自语言包，两者要一起挂。反过来只挂语言包（不挂真库）时它会被判为 `data`（与主库 0% 重叠），行为与本次改动前完全一致。
