> 需求：卡组编辑器的卡片搜索只有关键字框，没有多维度筛选；拖拽手感发涩；点击「加入卡组」后看不出卡片落到哪里。
> 实现选择：筛选不另写一份 store 与控件，直接复用主窗口的 `useCardSearchStore` + `FilterDrawer`（卡组编辑器是独立渲染进程，天然各持一份实例）；拖拽只调过渡曲线、命中策略与落位反馈，不动布局算法。
> 参考出处：`mdpro3/MDPro3-master/Assets/Scripts/MDPro3/UI/ServantUI/DeckEditorUI.cs` 的 `AddCardFromCollection` / `DragCardTo` / `PlayDragCardShrinkAnimation`。它是 Unity 客户端源码，能抄的只有交互意图（按插入序列定位、落位要有收缩反馈、加卡后刷新计数），`GetSiblingIndex()`、`UIHover.HoveringLabel` 这类 UI 树概念在 React 里没有对应物，不能照搬。

## 第二步：加入卡组要有落点

**`src/renderer/src/components/DeckEditor/DeckEditorApp.tsx`**

点击、拖入、右键三条路径原先各走各的（点击直接 `addCard`，拖入失败才弹 toast），收敛成一个 `handleAddCard`：先算实际落入的分区，失败弹提示，成功则给落位那张卡一次 700ms 的高亮。这是 MDPro3 `PlayDragCardShrinkAnimation` 的等价物——那里是让拖拽卡在落点收缩淡出，这里没有可复用的拖拽节点，改成给目标位置打高亮，同样解决「不知道加到哪去了」。

分区不能只看入参：`addCard` 在没传 section 时会按 `CardUtils.isExtraDeck` 自己挑区，外层要拿同一个结果才能定位落点，所以复制了它的判定而不是另写一套。

```diff
+  const handleAddCard = useCallback(
+    (card: CdbCard, section?: DeckSection, index?: number): boolean => {
+      const ok = addCard(card, section, index)
+      const resolved: DeckSection = section ?? (CardUtils.isExtraDeck(card.type) ? 'extra' : 'main')
+      if (!ok) {
+        showRejectToast(resolved)
+        return false
+      }
```

跨区移动同样补了落位高亮（原来只有失败才有反馈，成功时卡片「嗖」地换了个区，看不出去了哪）。

**`src/renderer/src/components/DeckEditor/DeckCardItem.tsx` / `DeckGrid.tsx`**

高亮用卡片自身的 `ring` 而不是内部覆盖层：根元素带 `overflow-hidden`，放在里面的 `animate-ping` 会被裁成半截。ring 走 box-shadow，而元素上本来就有 150ms 的 box-shadow 过渡，于是高亮自带淡入淡出，不用另写关键帧。

```diff

## 第三步：拖拽手感

**`src/renderer/src/components/DeckEditor/DeckEditorApp.tsx`**

+}
```

**`DeckSearchPanel.tsx`** 里搜索卡补了拖拽中的 `opacity-40`（原先拖起来后源卡毫无变化，起手那一下没有反馈），并加了右键菜单直接指定加入主/额外/副卡组——额外怪兽想进副卡组原本只能先加进去再拖过去。
