# 游戏王决斗编辑器：主卡组面板（卡组库载入 / 换卡组 / 抽卡 / 卡序）

本改动属于一次独立的原子化功能提交。目标是打通「在卡组库里预先配好卡组 → 回到决斗盘一键取用」的创作闭环：此前只能通过卡组编辑器窗口里的「载入决斗盘」按钮把卡组送进场，而决斗盘本身的主卡组格几乎没有任何入口。本次把主卡组格升级为一个完整的**卡组面板**，并在同一次改动里修正了「卡组顶」方向长期存在的语义不一致。

---

## 改动缘由与核心设计目标

### 1. 主卡组格缺少入口

决斗盘上的主卡组格（`CardLocation.DECK`）原先只有一个「双击查看列表」和一个右上角张数徽章，两者都指向同一个只读性质的列表弹窗：

- 单击：无任何作用（只有 `if (!card) setSelectedCardId(null)` 的取消选中）；
- 双击：`openPile(controller, DECK)`；
- 右上角计数徽标：`openPile(controller, DECK)`。

也就是说，**「我想换一副卡组」这件事在决斗盘上无路可走**，必须切到卡组编辑器窗口、找到目标卡组、再点「载入决斗盘」。本次把单击（与双击）统一升级为「打开卡组面板」，面板里同时承载载入、切换、抽卡与卡序调整四件事。

### 2. 单击 / 双击的冲突问题

用户最初设想「单击抽卡」，但需要先厘清一个事实：**浏览器里单击与双击是两个独立事件，本身不会互相冲突，但一次双击必定先派发两次单击**。若做成「单击抽卡 + 双击开面板」，双击时就会先白白抽掉两张，只能靠 200ms 延迟判定规避，而抽卡是每回合都要做的高频操作，这个延迟不可接受。

因此最终方案让单击与双击**指向同一个行为**（都打开卡组面板），从根上消除歧义：不存在误抽，也不需要防抖。

### 3. 点击事件被卡片吞掉的问题

主卡组格内渲染的 `CardItem` 在自己的 `onClick` 里调用了 `e.stopPropagation()`（这是为了让点击卡片只选中卡片、不冒泡到格子的取消选中逻辑）。若把打开面板的逻辑挂在格子根节点的**冒泡阶段**，就会出现「点格子边缘能开面板、点卡面没反应」的诡异手感。本次改用 **`onClickCapture` 捕获阶段**挂载，捕获先于子元素执行且不受子元素 `stopPropagation` 影响，卡面与边缘行为完全一致。

### 4. 空卡组自动展开卡组库

卡组为空时，用户点开面板的意图**必然是**「挑一副卡组载入」。此时把卡组库列表默认展开，使完整链路压缩到两步：**点主卡组格 → 点卡组**。已有卡组时则默认收起，让卡片列表占满空间。

### 5. 「卡组顶」方向修正（语义不一致）

这是本次顺带修掉的既有缺陷。原实现里：

- `applyDeckToPlayer` 把 `deck.main[0]` 放进 `sequence = 0`，依此类推；
- 卡组面板列表按 `sequence` 升序从左到右展示，即最左是 `主卡[1]`；
- 但 `executeDrawCard` 取的是 `deckCards[deckCards.length - 1]`，即 **`sequence` 最大的一张 = 列表最右**。

结果是「列表第一张」与「实际下一抽」相反，用户若靠拖动列表来编排抽卡顺序会完全对不上。本次统一为 **`sequence` 最小 = 卡组顶 = 下一抽 = 列表最左**，并同步修正：

- `executeDrawCard` 取 `sequence` 最小者；
- `DuelBoard.getCard` 对主卡组返回 `sequence` 最小者（格子上显示的就是下一张会抽到的卡）。

另外 `executeDrawCard` 原先直接按 `cards` 数组的**物理顺序**取末位，而列表重排（`reorderPileCards`）与移入移出都会让数组顺序与 `sequence` 脱钩——这里改为**显式按 `sequence` 排序**后再取，属于同一个 bug 的另一半。

## 交互速查

| 操作                        | 位置               | 行为                                                |
| --------------------------- | ------------------ | --------------------------------------------------- |
| 单击 / 双击主卡组格         | 我方或对方主卡组格 | 打开卡组面板                                        |
| 单击右上角张数徽标          | 主卡组格           | 打开卡组面板                                        |
| 「从卡组库载入」            | 面板工具条         | 展开 / 收起卡组库列表（可搜索卡组名 / 分组 / 标签） |
| 点卡组库中的一副卡组        | 面板工具条下方     | 按「载入时手牌」设定整体替换该方主卡组与额外卡组    |
| 「载入时手牌：全留 / 抽 5」 | 面板工具条         | 决定载入瞬间是否模拟起手抽 5（默认全留）            |
| 「抽 1 张」                 | 面板工具条         | 把列表最左（下一抽）那张抽到手牌，可连点            |
| 左右拖动白色卡框            | 面板卡片列表       | 调整卡序，即调整后续抽卡顺序                        |

> 抽 5 只在**载入卡组那一刻**发生一次，之后每回合都是单张抽取，不存在「每回合都抽 5 张起手」的问题。抽卡可随时用 `Ctrl+Z` 撤销。

## 已知边界与后续

- **卡组编辑器窗口内的卡序拖拽**：本次未做，该窗口目前仅有「排序」按钮，属于独立改动面，留待后续单独提交。
- **卡组库面板的排序**：沿用 `getDeckList()` 的原始顺序，未做自定义排序。
- **「当前已载入的是哪副卡组」**：决斗状态里没有记录卡组来源 ID，面板因此只提供「从卡组库载入」入口而不显示「当前卡组名」。若后续需要，应在 `DuelPuzzleState` 里为双方各加一个可选的 `deckRef`（并做版本迁移）。
