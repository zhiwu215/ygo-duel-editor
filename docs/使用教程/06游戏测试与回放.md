## 四条路径的区别

![image-20261026133542071](../images/image-20261026133542071.png)

| 功能             | 导出内容        | 需要引擎                | 支持人数      | 进游戏方式                  |
| ---------------- | --------------- | ----------------------- | ------------- | --------------------------- |
| 使用游戏测试该局 | 当前盘面的 Lua  | 不需要                  | 1v1           | 自动启动（EDOPro 需手动选） |
| 导出脚本         | 当前盘面的 Lua  | 不需要                  | 1v1、2v2 标准 | 手动加载                    |
| 导出对局回放     | YRP/YRP3D + Lua | 需要，且至少有 1 个操作 | 1v1、2v2 标准 | 自动启动（EDOPro 需手动）   |
| 导入对局回放     | 读取 YRP/YRP3D  | 会用引擎重放            | 1v1、2v2 标准 | 在编辑器里看                |

## 导出对局回放

![image-20261026140335390](../images/image-20261026140335390.png)

### 前置条件

- 当前有引擎会话
- 引擎时间线至少有 1 个操作（不只是初始节点）
- 对阵是 1v1 或 2v2 标准
- 引擎会话里**没有注入操作**（手动加卡、替换、置顶/置底等）

> YRP 回放只记录开局盘面和之后的应答流，对局中途注入的卡不会写进回放。如果时间线里有「注入」步骤，导出会被拒绝；强行导出会让游戏在后续步骤报 `Error occurs.`
>
> 需要回放时请从无注入的开局重新对局；只想测试当前盘面请用「使用游戏测试该局」
>
> **开局**盘面/卡组里的占位卡在启动引擎后替换成正式卡，属于修改初始盘面，**不会产生注入步骤**；只有**引擎启动后通过「注入」加入的卡才会阻止导出**

### 它会做什么

1. 把引擎会话的响应流、种子、初始盘面打包成回放
2. 写一份对应的 Lua 到 `single/`（单人模式）
3. 写入游戏目录：
   - ygopro：`replay/<名称>.yrp` + `single/<名称>.lua`
   - MDPro3：`replay/<名称>.yrp3d` + `single/<名称>.lua`

### 回放文件依赖

单模式回放依赖同名的 `single/<名称>.lua`。如果只拷贝 `.yrp` 到另一台机器，没有对应 Lua，回放可能无法加载或无法还原初始场面。换机器时把 `replay` 和 `single` 一起带走

**1v1 单模式回放必须同时有 YRP 和 Lua 两个文件**（2v2 tag 回放除外，因为卡组信息写在 YRP 里，不需要单模式 Lua）

## 回放文件管理

- 只列出 `replay` 目录里同时存在同名 `single/*.lua` 的单模式回放
- 勾选后删除，会同时删除回放和对应 Lua
- 用于清理导出的测试回放，避免越积越多

### 回放控制

- **播放/暂停**：底部播放键，或空格；
- **上一步/下一步**：左右箭头，或 `←` / `→`；
- **速度**：0.5×、1×、1.5×、2×、3×；
- **回到开头**：旋转箭头；
- **退出回放**：回到导入前的工程；
- **编辑**：从当前回放步骤转成可编辑工程。

![image-20261026144717144](../images/image-20261026144717144.png)

### 编辑回放

点“编辑”：

1. 以当前回放步骤为分叉点；
2. 把该步之前的步骤保留；
3. 把当前盘面转成编辑器格式；
4. 退出回放，进入可编辑状态；
5. 标题会变成“A vs B”形式。

之后的步骤不会保留
