# 超量叠放层级修复与素材列表弹窗及拔除重构

本改动属于一次完整的原子化功能提交，旨在解决超量怪兽（XYZ Monster）在决斗台上的叠放层级混乱、快捷键冲突、素材查阅盲区以及右键菜单冗余等一系列交互体验问题。通过重构 Alt 拖拽叠放层级、扩展底层超量素材操作 Action、引入专属的轻量化素材弹窗 Store 与全景平铺弹窗、为场上怪兽常驻素材数量徽标并支持双击呼出，最终精简右键菜单与详情栏的冗余元素，建立起符合游戏王官方决斗习惯的超量做场与素材管理体系。

---

### 第一步：快捷键冲突精简与超量叠放层级修复

- **思考与缘由**：
  在早期的实现中，叠放卡片支持 `Shift` 与 `Alt` 作为修饰键。但实际操作中，浏览器及宿主系统对 `Shift` 键伴随有文本/多选的原生行为捕获，导致按住 `Shift` 时往往无法正常触发拖拽卡片。因此将快捷键收敛为纯粹的 `Alt + 拖放`，并在顶部菜单栏的快捷键参考中同步更新。
  同时，原有的拖放叠放逻辑是直接将新卡 push 到已有素材列表的末尾。这会导致致命逻辑错误：当用户使用超量怪兽直接叠放在怪兽上做场（如「天霆号 阿宙斯」或「SNo.39 希望皇 霍普·电光皇」），或者从额外卡组拖出超量怪兽叠放在场上怪兽上时，超量怪兽反而被压在最底层，原怪兽仍停留在顶层主卡位。因此必须在拖放处理中增加智能层级判定：
  1. 若拖入的是超量怪兽（或场上原卡非超量），新卡必须作为顶层主怪兽（Host），原怪兽及其原有素材全数垫入下方；
  2. 仅当场上已有超量怪兽且拖入普通怪兽卡时，才保持场上超量怪兽置顶，将新卡垫入下方素材堆。

#### 叠放拖拽数据流解析

在实现 `Alt + 拖放` 叠放逻辑的过程中，围绕拖拽数据源的识别与数据完整性进行了专门的梳理与重构：

- **拖拽实例标识与自叠放拦截**：
  通过 `dataTransfer.getData('text/instanceId')` 读取鼠标抓起的卡片在场上的唯一实例 ID（`movedInstanceId`）。如果该 ID 与目标格子上已有的 `card.instanceId` 相同，说明用户拖动卡片后又放回了原怪兽身上。系统直接拦截并终止，防止怪兽“自己叠放自己”导致自身卡片被吃掉变成素材。
- **卡片数据与场上原位追踪**：
  引入 `incomingCard`（记录卡片的类型、星级、攻防等属性，用于判断是否为超量怪兽以决定层级）与 `incomingSourceId`（记录其原本所在的场上格子）。若卡片来自场上或手牌，叠放后必须移走原位置的旧卡，防止卡片被非预期克隆；若来自右侧搜索栏，则作为新卡直接叠放。
- **搜索面板与场内卡片双通道解析**：
  叠放操作支持两种用户交互习惯：既支持从场上/手牌拖拽怪兽叠放，也支持直接从右侧搜索栏抓取新卡叠放。逻辑上优先从场上卡片缓存中读取 `movedCard.card`；若未取到（即从搜索栏拖入的新卡），则自动从 `application/json` 数据通道中解析反序列化真实的 `CdbCard` 对象。

### 第二步：底层超量素材核心动作与弹窗状态 Store 构建

- **思考与缘由**：
  在确定了叠放层级后，编辑决斗局面时常常需要更细粒度的编排控制能力：例如用户叠错素材想要更换、拔除素材发动效果送去墓地、将素材移入除外或手牌、或者将某张素材卡一键提升为主怪兽。
  为此，在 `useDuelStore` 中新增了 `overlayOnTop`（新怪兽置顶叠放）、`swapHostWithMaterial`（顶层主怪兽与素材互换）、`detachMaterialToLocation`（拔除素材送至指定区域并在目标区域生成场上卡片实例）、`reorderOverlayMaterials`（重排素材层级）等纯函数 Action。
  同时，为解耦弹窗的呼出状态，新建 `useOverlayListStore` 独立记录当前正被查看素材列表的超量怪兽 `hostInstanceId`。

#### 超量置顶状态流转与千层饼素材重构

在实现 `overlayOnTop` 的过程中，围绕状态快照、来源怪兽语义、场面属性继承与素材堆叠进行了专门的梳理与规范化：

- **函数式快照与状态稳定性**：
  在 `set((prev) => ...)` 中，`prev` 即更新前 Store 的完整状态快照（`previous state`）。通过函数式更新确保基于最新状态读取 `cards` 列表与选中状态，避免竞态与闭包过期问题。

- **超量主角与来源卡语义辨析**：
  将原本易生歧义的参数 `removeSourceInstanceId` 重构为 `sourceCardInstanceId`。在业务逻辑中，该 ID 代表的是被抓起准备登场的主角怪兽（如从 1 区拖过来的「电光皇」），而非要丢弃的素材。做场时需读取其身上已有的素材（`sourceMats`）以便向下继承，并在完成转移后清理其旧格子，避免场上产生重复怪兽。

- **场面物理属性继承与千层饼结构重组**：
  在遍历更新卡片时，通过 `...c` 继承单张场上怪兽（`FieldCard`）原有的格子序号（`sequence`）、控制者（`controller`）、攻守表示形式（`position`）以及指示物等物理属性不变；同时重构 `overlayMaterials` 数组，形成规范的“千层饼”堆叠：
  - 最底层：宿主原本持有的底层老素材（`...c.overlayMaterials`）；
  - 中间层：宿主怪兽本体退下神坛，变成素材卡密（`c.code`）；
  - 上层素材：登场怪兽自身自带的素材合并垫入（`...sourceMats`）；
  - 顶层核心：由新卡全面接管卡密（`code`）与详情（`card`），成为场上崭新的主怪兽。

- **选中高亮光标的平滑转移**：
  在返回的新状态中，通过三元表达式评估 `selectedCardId`。若用户在拖放前正选中着来源怪兽，叠放后选中的蓝框高亮会自动平滑转移至新目标怪兽，保证选中焦点连贯，防止光标丢失。

### 第三步：超量怪兽素材数量常驻徽标与双击直达交互

- **思考与缘由**：
  在经典 OCG/Master Duel 视觉中，超量怪兽哪怕没有素材（0个），也应当常驻标明素材数量为 0，以便编排者区分其当前能否发动取除素材的效果。同时，为了让查阅素材列表像查看额外卡组列表一样顺手，需要在 `CardItem.tsx` 中增加：

  2. 点击该角标或在怪兽卡片上**直接双击**，即可立即唤起超量素材列表弹窗；
  3. 卡片横置守备表示时，徽标位置通过 `oruPos` 坐标矩阵自适应落点在视觉右下角。

### 第七步：超量怪兽守备表示时素材保持纵向正立

- **思考与缘由**：
  在实际对局（如 YGOPro、Master Duel）与官方 OCG/TCG 规则中：
  - **超量素材不具备表示形式**：超量素材并非场上的卡，不存在“攻击表示”或“守备表示”的状态属性；
  - **视觉十字叠放形态**：当超量怪兽由攻击表示转为守备表示（横置 90°）时，仅顶层超量怪兽本体发生横向旋转，底下的超量素材始终保持纵向正立（0°）。此时纵向卡片的上下两端自然从横置怪兽卡片边缘露头，形成经典的游戏王超量守备“十字叠放”视觉效果；
  - **旋转容器解耦**：原先外层父容器绑定了 `animate={{ rotate: isDefense ? 90 : 0 }}`，导致所有素材图层随同怪兽本体一并横置旋转。需将旋转动画抽离并专属挂载至顶层主怪兽卡片，底层素材容器保持独立静止正立。
