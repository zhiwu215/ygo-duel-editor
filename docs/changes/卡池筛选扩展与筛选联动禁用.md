# 卡池筛选扩展与筛选联动禁用

## 一、改动缘由

对接游戏内（YGOPro）的筛选体验，本次共三件事：

1. **卡池筛选项不全**。项目里卡池这一概念早已存在——设置窗口给每个附加卡库（`anime.cdb` / `rush.cdb` 等）指定所属卡池标记，检索结果里带 `pools` 字段并显示角标。但筛选抽屉的「赛区卡池」下拉只暴露了 `any / ocg / tcg / both` 四项，附加库的卡池标记一直没有进入筛选条件；YGOPro 还有「OCG 独有 / TCG 独有」两项也没有。
2. **筛选项之间没有联动**。YGOPro 里，卡片大类选「（无）」时细分类型、属性、种族、攻守、星级、刻度全部置灰不可选；选魔法/陷阱时只留细分类型可选。本项目这些项任何时候都能选，会筛出空集。
3. **没加载对应库时不该出现的选项仍然出现**。第一版按「有库才可选、无库置灰」实现，实测仍不合适——用户希望未加载 `anime.cdb` / `rush.cdb` 等库时，这三个卡池项**直接不显示**。

## 二、卡池的两种判定口径

卡池筛选分两类，判定依据不同：

| 选项 | 判定依据 | 说明 |
| --- | --- | --- |
| OCG / TCG | 卡片 `ot` 位（`0x1` / `0x2`） | 卡片可在该赛区使用即可 |
| OCG 独有 / TCG 独有 | 卡片 `ot` 位 | 只有该赛区、另一个不包含 |
| 动漫/漫画 / 超速（Rush）/ 卡片力量（TF） | **所属卡库标记**（`cdbPoolTags`） | 只检索被标记为该卡池的附加库 |

第一类严格对齐 YGOPro `deck_con.cpp:1539-1554` 的 `filter_lm` 分支：

```
filter_lm == 4 → (ot & AVAIL_OCG)              // OCG
filter_lm == 5 → (ot & AVAIL_TCG)              // TCG
filter_lm == 8 → (ot & AVAIL_OCG) && !(ot & AVAIL_TCG)   // OCG 独有
filter_lm == 9 → (ot & AVAIL_TCG) && !(ot & AVAIL_OCG)   // TCG 独有
```

第二类的实现方式：`CdbService.search()` 遍历已加载的连接时，若 `cardPool` 是 `anime/rush/tf`，则跳过 `poolId` 不匹配的库（含无标记的主库）。「有没有这个卡池」完全取决于用户是否加载并标记了对应附加库——与 YGOPro 的实际表现一致。

**为什么不用 `ot` 位判定动漫/超速/TF**：实测用户本地的 `anime.cdb` 中，`ot & 0x10` 共 301 条，其中只有 51 条卡名带 `(TF)`、28 条带 `(Anime)`，剩下 222 条两者都不带——这一位是混合桶，不能干净地切出「卡片力量」；超速卡的 `ot` 位同样只在特定库中才有意义。按库标记判定最可靠，且与既有架构（用户自己给库打标）一致。

## 三、OCG / TCG 独有角标

独有卡用 `ot.png` 的第 1、2 行（`spriteY = 0 / 64`）。**只有当前卡池筛选选中「OCG 独有 / TCG 独有」时才显示**——此时列表里全部是独有卡，角标用来标明该卡是 OCG 独有还是 TCG 独有；其它筛选（全部卡池 / OCG / TCG / 动漫漫画 / 超速 / TF）下一律不显示，与游戏内表现一致（游戏只在按独有筛选时列表才带 `[OCG]` / `[TCG]`）。

```ts

/** 返回卡片需要显示的独有角标 id 列表（只含单一赛区位时才有值） */
export function otBadgeIds(ot: number): string[] {

  const hasTcg = (ot & AVAIL_TCG) !== 0
  if (hasOcg && !hasTcg) return ['ocg']
  if (hasTcg && !hasOcg) return ['tcg']

}
```

### 4. 筛选联动禁用（对齐 YGOPro `COMBOBOX_MAINTYPE`）

YGOPro 源码（`gframe/deck_con.cpp:886-1010`）的规则：

- 大类 = 「（无）」：`cbCardType2`（细分类型）、`cbRace`、`cbAttribute`、攻/守/星级/刻度 全部 `setEnabled(false)`，并把细分类型 `setSelected(0)`；
- 大类 = 怪兽：上述全部启用；
- 大类 = 魔法 / 陷阱：只启用细分类型，属性/种族/攻守/星级/刻度禁用；
- 细分类型 = 连接（Link）：禁用守备力（Link 怪兽没有守备力）。

本项目对应实现：

```ts
const isAllTypes = type === 0
const detailDisabled = isAllTypes || type === CardType.SPELL || type === CardType.TRAP
const subTypeDisabled = isAllTypes
const defDisabled = detailDisabled || isLinkMonster
```

- `细分类型` → `disabled={subTypeDisabled}`
- `属性` / `种族` / `等级` / `刻度` / `攻击力` / `连接标记` → `disabled={detailDisabled}`
- `守备力` → `disabled={defDisabled}`（连接怪兽额外禁用）

切换大类时同步清空从属字段（对应 YGOPro 的 `setSelected(0)`）：

```diff
                 setFilters({
                   type: num,
                   subType: 0,
-                  ...clearDefIfLink(markers, 0, num)
+                  attribute: 0,
+                  race: 0,
+                  level: 0,
+                  scale: undefined,
+                  atk: undefined,
+                  def: undefined,
+                  defOp: 'eq',
+                  markers: 0
                 })
```

`CompareRow` 组件本就有 `disabled` 支持（条件选择器与数值输入一并禁用）。
