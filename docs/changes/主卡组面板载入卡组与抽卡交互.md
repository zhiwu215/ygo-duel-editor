# 游戏王决斗编辑器：主卡组格交互（单击抽卡 / 双击列表 / 右键切换卡组）

本改动把决斗盘上的**主卡组格**（`CardLocation.DECK`）升级为一个可日常使用的编排入口，打通「在卡组库里预先配好卡组 → 回到决斗盘一键取用 → 逐回合抽卡推演」的创作闭环。此前只能通过卡组编辑器窗口里的「载入决斗盘」按钮把卡组送进场，决斗盘的主卡组格几乎没有任何入口。

> **迭代说明**：本文件记录的是**最终方案**。第一版实现（`c0cf69a`）曾把「单击 / 双击都打开卡组面板」作为主交互，实测后用户认为单击开面板手感别扭，且指出「载入卡组时卡组是正面表示的」这一缺陷。本版据此把交互重做为 **单击抽卡 / 双击展开列表 / 右键切换卡组**，并把载入的卡组改为里侧渲染。第一版中位于卡组面板里的卡组库工具条已全部回退，改由独立的「切换卡组」弹窗承载。

---

## 改动缘由与核心设计目标

### 1. 单击到底该做什么：抽卡 vs 开面板

用户最初设想「单击抽卡」，第一版出于「避免单击与双击冲突」的考虑，把单击与双击统一成「打开卡组面板」。实测后用户认为**单击开面板太重**：日常推演里最高频的动作是抽卡，而换卡组是低频动作，两者不该共用一个入口。

最终把职责拆开，各归其位：

| 动作         | 行为                      | 频率 |
| ------------ | ------------------------- | ---- |
| 单击主卡组格 | 抽 1 张到手牌             | 高频 |
| 双击主卡组格 | 展开卡组列表（调序/查看） | 中频 |
| 右键主卡组格 | 弹出菜单 → 「切换卡组」   | 低频 |
| 单击张数徽标 | 展开卡组列表              | 中频 |

### 2. 单击 / 双击的冲突问题（必须延迟判定）

**浏览器里单击与双击是两个独立事件，本身不冲突，但一次双击必定先派发两次单击。** 因此「单击抽卡 + 双击开列表」若直接实现，双击时就会先白白抽走两张。

规避方式：单击抽卡**延后约 240ms** 执行；若这期间来了双击，由 `cancelDeckDraw()` 取消待执行的抽卡。

- 240ms 覆盖绝大多数双击间隔（Windows 默认双击阈值约 500ms，但用户实际操作间隔普遍在 150~250ms）；
- 万一没覆盖到，多抽的那张可用 `Ctrl+Z` 撤销（抽卡本身在 undo 历史内）；
- 定时器在组件卸载时统一清理，避免销毁后仍触发抽卡。

### 3. 点击事件被卡片吞掉的问题

主卡组格内渲染的 `CardItem` 在自己的 `onClick` / `onDoubleClick` / `onContextMenu` 里调用了 `e.stopPropagation()`（这是为了让点击卡片只选中卡片、不冒泡到格子的取消选中逻辑）。若把主卡组格的逻辑挂在**冒泡阶段**，就会出现「点格子边缘能抽卡、点卡面没反应」的诡异手感。

因此主卡组格改用**捕获阶段**（`onClickCapture` / `onDoubleClickCapture` / `onContextMenuCapture`）挂载，捕获先于子元素执行且不受子元素 `stopPropagation` 影响，卡面与边缘行为完全一致。

### 4. 计数徽标的例外

格子右上角的张数徽标本身就带「打开列表」行为。若不加区分，点徽标会同时触发「格子抽卡」与「徽标开列表」。故给徽标加 `data-zone-badge` 属性，主卡组格的处理器用 `isFromZoneBadge(e)` 判断并放行——不抢单击、不抢双击。

### 5. 空卡组也要能换卡组

尚未载入卡组时，格子里没有任何卡片，右键没有「卡片」可依附。因此把右键菜单的**目标类型**从「卡片」扩展为「卡片 | 区域」两种：右键**空**的主卡组格时，由格子自身提供区域级菜单（内含「切换卡组」）。有卡片时则放行给 `CardItem` 走常规卡片菜单（其中也已含「切换卡组」）。

### 6. 载入的卡组必须里侧备着

用户指出「载入卡组时卡组都是正面表示的，不行」——卡组在实机里是**里侧堆着**的，且某些卡的效果会翻转卡组，正面显示会看不清。

根因是 `applyDeckToPlayer` 用 `CardPosition.FACEDOWN_ATTACK`（`0x2`）存放主卡组/额外卡组。而 `CardItem` 的 `isFacedown` 判定只看 `FACEDOWN(0xa)` 与 `FACEDOWN_DEFENSE(0x8)`，**`0x2` 不在其内**，于是被当成表侧渲染出卡面。改为 `CardPosition.FACEDOWN` 即可。

里侧的渲染方式参考盖放魔陷：

- **主卡组**：保留清晰卡面 + 暗化蒙版（`bg-black/25` + 琥珀描边），**但不打左上角「盖放」角标** —— 卡组只表示「里侧备着」，打上角标会被读成一张被盖放的卡；
- **额外卡组**：保留卡背（额外卡组按原样堆着，卡背最直观）；
- 若卡组被效果翻成表侧，`position` 变为表侧，暗化自然消失，「盖放」角标语义不被占用。

### 7. 「卡组顶」方向修正（顺带修掉的既有缺陷）

原实现里：

- `applyDeckToPlayer` 把 `deck.main[0]` 放进 `sequence = 0`，依此类推；
- 卡组列表按 `sequence` 升序从左到右展示，即最左是 `主卡[1]`；
- 但 `executeDrawCard` 取的是 `deckCards[deckCards.length - 1]`，即 **`sequence` 最大的一张 = 列表最右**。

结果是「列表第一张」与「实际下一抽」相反。本次统一为 **`sequence` 最小 = 卡组顶 = 下一抽 = 列表最左**，并同步修正：

- `executeDrawCard` 显式按 `sequence` 升序排序后取 `[0]`（原先直接按 `cards` 数组**物理顺序**取末位，而列表重排与移入移出都会让数组顺序与 `sequence` 脱钩，属于同一 bug 的另一半）；
- `DuelBoard.getCard` 对主卡组返回 `sequence` 最小者（格子上显示的就是下一张会抽到的卡）。

## 交互速查

| 操作                          | 位置                | 行为                                           |
| ----------------------------- | ------------------- | ---------------------------------------------- |
| 单击主卡组格                  | 我方 / 对方主卡组格 | 抽 1 张到手牌（列表最左 = 卡组顶），可连点     |
| 双击主卡组格                  | 主卡组格            | 展开卡组列表（查看 / 调序）                    |
| 右键主卡组格（有卡 / 空皆可） | 主卡组格            | 弹出菜单 → 「切换卡组」                        |
| 单击右上角张数徽标            | 主卡组格            | 展开卡组列表                                   |
| 点卡组库中的一副卡组          | 「切换卡组」弹窗    | 按「载入手牌」设定整体替换该方主卡组与额外卡组 |
| 「载入手牌：无 / 抽 5」       | 「切换卡组」弹窗    | 决定载入瞬间是否模拟起手抽 5（默认「无」）     |
| 左右拖动白色卡框              | 卡组列表面板        | 调整卡序，即调整后续抽卡顺序                   |

> 抽 5 只在**载入卡组那一刻**发生一次，之后每回合都是单张抽取，不存在「每回合都抽 5 张起手」的问题。抽卡可随时用 `Ctrl+Z` 撤销。

## 已知边界与后续

- **卡组编辑器窗口内的卡序拖拽**：本次未做，该窗口目前仅有「排序」按钮，属于独立改动面，留待后续单独提交。
- **卡组库面板的排序**：沿用 `getDeckList()` 的原始顺序，未做自定义排序。
- **「当前已载入的是哪副卡组」**：决斗状态里没有记录卡组来源 ID，弹窗因此只提供「切换卡组」入口而不显示「当前卡组名」。若后续需要，应在 `DuelPuzzleState` 里为双方各加一个可选的 `deckRef`（并做版本迁移）。
- **单击抽卡的 240ms 延迟**：极端慢速双击（间隔 > 240ms）仍可能多抽一张，属可接受的权衡（可用 `Ctrl+Z` 撤销）。若日后要彻底消除，可改为「单击即抽、双击不额外抽」并把列表入口完全交给徽标 / 右键。
