# 场上卡片旋转过渡与盖放清晰度角标重构

本改动属于一次独立的原子化提交，聚焦于决斗盘场上卡牌的拖动放置动效、里侧盖放卡牌的高清透光质感，以及横竖表示形式切换时状态角标的物理定位与视觉呈现优化。

---

## 思考与改动明细（按开发推导顺序）

### 1. 解决跨格子拖移卡片时的组件身份丢失与冗余旋转动画

- **改动文件**：**src/renderer/src/components/Board/ZoneSlot.tsx**
- **开发思考与缘由**：
  在决斗盘上将一张已处于横置守备表示的卡牌拖拽到另一个格子时，界面上卡牌会突兀地经历一次“从 0°（立姿）重新旋转到 90°（横姿）”的补间动画。
  分析其根本原因：每个槽位在渲染 `<CardItem>` 时未显式传入 `key` 属性。当卡片从槽位 A 移到槽位 B，React 的 Diff 机制将其视为“槽位 A 卸载、槽位 B 挂载新组件”，导致新挂载的卡片重新执行一次由攻击到守备的入场过渡。
  因此，在 **src/renderer/src/components/Board/ZoneSlot.tsx** 中为 `<CardItem>` 绑定全局唯一的 `card.instanceId` 作为 `key`，使 React 正确识别卡片实例的物理移动，保持组件身份的一致性。

+        <CardItem key={card.instanceId} card={card} squareCell={isSquareCell} />

### 2. 抑制初次挂载无效动画并消除 CSS 属性冲突

- **改动文件**：**src/renderer/src/components/Board/CardItem.tsx**
- **开发思考与缘由**：
  即使具备了 `key`，在全新放置一张守备表示卡片时，Framer Motion 的 `<motion.div>` 默认会以初始状态 (`rotate: 0`) 执行入场动画。守备卡片落子时并不需要从攻击姿态硬转 90°，而应当直接以守备姿态落入。
  同时，容器类名中原有的 Tailwind `transition-all` 包含了对 `transform` 的 CSS 补间控制，这会与 Framer Motion 的 Spring 物理引擎在驱动 `rotate` 时发生属性竞争，造成微小掉帧或旋转卡顿。
  因此，在 **src/renderer/src/components/Board/CardItem.tsx** 中：
  1. 为卡牌主体 `<motion.div>` 加上 `initial={false}`，彻底禁止挂载时的非必要旋转回放；
  2. 移除 `transition-all`，将形变与旋转完全交由弹簧动效引擎统一接管。

```diff
       <motion.div
+        initial={false}
         animate={{ rotate: isDefense ? 90 : 0 }}
         transition={{ type: 'spring', stiffness: 300, damping: 25 }}
-        className={`relative rounded overflow-hidden shadow-md transition-all ${
+        className={`relative rounded overflow-hidden shadow-md ${
           // 正方形格: 卡面按卡牌比例 (59:86) 缩放为 71×104，横置时仅旋转 90° 不再缩放；
           // 竖长格 (手牌/牌堆): 卡面完整填充
           squareCell ? 'w-[68.6%] h-full' : isDefense ? 'w-[68.6%] h-[71%]' : 'w-full h-full'
```

### 3. 剔除高斯模糊滤镜并校准里侧盖放卡面暗度与识别边框

- **改动文件**：**src/renderer/src/components/Board/CardItem.tsx**
- **开发思考与缘由**：
  在创作者全知视角下，场上盖放的卡牌需要兼具“清晰可读”与“明显是里侧盖放状态”两项诉求：
  1. 此前设计尝试引入了 `backdrop-blur-[0.5px]`。但在 71×104 的小卡牌视口中，任何高斯模糊或降采样算法都会严重劣化文字与细节边缘，直接导致卡名、星级和攻防数据发虚模糊；
  2. 此前的暗色遮罩达到了 45%（`bg-slate-950/45`），使得暗色怪兽与深色卡图完全沦为一团黑影，辨识极为费力；而单纯的 10% 遮罩在明亮场景下盖放感又稍显不足。
     因此，在 **src/renderer/src/components/Board/CardItem.tsx** 中：
  3. 彻底移除所有 `backdrop-blur`，确保卡图以 100% 原生高清晰度呈现，细节丝毫不发糊；
  4. 遮罩平衡调整为 `bg-black/25`（25% 适度遮光），既能形成鲜明的“置于阴影中/隐匿状态”视觉语意，又完全不损伤卡图色彩饱和度；
  5. 附带一层柔和的琥珀金内边框（`border border-amber-400/50 rounded`），使盖放卡片即便在不放大时也能凭借暗金轮廓一眼识别。

### 4. 角标脱离旋转容器与基于视觉顶角的平滑坐标映射

- **改动文件**：**src/renderer/src/components/Board/CardItem.tsx**
- **开发思考与缘由**：
  在之前的实现中，为了让角标跟随卡片，将角标组件放置在旋转的 `<motion.div>` 内部并施加 `-90°` 的反向抵消旋转。然而这种方案存在严重的几何与渲染缺陷：
  1. 卡片横置旋转是以卡牌几何中心为轴旋转的。内部原本位于底部的坐标经过 90° 顺时针旋转后，映射到了卡片的左侧腰部位置；
  2. 卡牌主体具有 `overflow-hidden` 样式，反转后的角标部分区域直接被外部矩形裁切了一半；
  3. 抵消旋转矩阵导致胶囊徽标边框产生次像素抖动，文字不够锐利。

  正确的几何解法是将角标置于外层未旋转的 104×104 容器中，直接根据攻击/守备形态计算卡牌实际在视野中的物理四角：
  - **正方形交互格（104×104）**：
    - 攻击表示（竖卡 71.3×104 居中）：左侧留白约 16.3px，视觉左上角为 `{ top: 3px, left: 18px }`，右下角为 `{ bottom: 3px, right: 18px }`；
    - 守备表示（横卡 104×71.3 居中）：顶部留白约 16.3px，视觉左上角为 `{ top: 18px, left: 3px }`，右下角为 `{ bottom: 18px, right: 3px }`。
  - **非正方形长条格（手牌/牌堆）**：
    - 保持边角自然对齐 `{ top: 3px, left: 3px }`。

  在 **src/renderer/src/components/Board/CardItem.tsx** 中计算 `badgePos`、`oruPos` 和 `counterPos` 动态坐标，并将状态徽标、超量素材数和指示物移出旋转盒子：

+  // 当正方形格竖置 (!isDefense) 时，卡片视觉为 71.3x104，横向居中 (left 留白约 16.3px)
