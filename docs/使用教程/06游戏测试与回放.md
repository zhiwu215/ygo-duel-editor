## 四条路径的区别

![image-20261026133542071](../images/image-20261026133542071.png)

| 功能             | 导出内容        | 需要引擎                | 支持人数      | 进游戏方式                  |
| ---------------- | --------------- | ----------------------- | ------------- | --------------------------- |
| 使用游戏测试该局 | 当前台面的 Lua  | 不需要                  | 1v1           | 自动启动（EDOPro 需手动） |
| 导出脚本         | 当前台面的 Lua  | 不需要                  | 1v1、2v2 标准 | 手动加载                    |
| 导出对局回放     | YRP 或 YRP3D，视格式和设置附带 Lua | 需要，且至少有 1 个操作 | 1v1、2v2 标准 | 可用游戏打开（EDOPro 需手动） |
| 导入对局回放     | 读取 YRP/YRP3D  | 会用引擎重放            | 1v1、2v2 标准 | 在编辑器里看                |

### 幸运相关操作说明

#### 卡片随机结果说明

对于卡片的效果（投骰子、投硬币、随机选卡）

之所以会产生随机结果，是因为对局一开始，引擎就会生成随机种子

之后所有卡片的随机效果都由这个随机种子计算得来

比如使用「圣杯 A」，如果你在引擎模式下发动，结果是正面，那么它这把游戏都是正面了，因为随机种子从对局开始就创建了，不会变动，而卡片的随机结果是由这个种子计算而来

我这个项目可以 Ctrl+Z 回退，乃至回退后进行各种召唤怪兽、发动效果，都不会产生任何影响，因为随机种子不变

但假如说你在此期间发动了其他的影响随机结果的卡片（投骰子、投硬币、随机选卡）

因为这种随机的卡片都共用同一个随机序列，那这张「圣杯 A」的随机数就是另一个了

这时候它有可能是正面也有可能是反面，当你投出来之后就是确定的

只有当你重新启动引擎模式的时候，这个随机种子才会变化

#### 引擎随机结果

![image-20261105180120225](../images/image-20261105180120225.png)

| 选项 | 行为                                                         |
| ---- | ------------------------------------------------------------ |
| 开启 | 默认。投硬币、掷骰子、随机选卡**完全由引擎决定**             |
| 关闭 | 遇到这三类随机时先停下来，弹窗**让你指定结果**，指定完再继续结算 |

## 导出对局回放

![image-20261026140335390](../images/image-20261026140335390.png)

### 前置条件

- 当前有运行中或可恢复的引擎会话
- 引擎时间线至少有 1 个操作（不只是初始节点）
- 引擎会话从第 1 回合的开局开始。若从中途盘面启动了引擎，需回到开局重新对局后再导出
- 对阵是 1v1 或 2v2 标准
- 会话有注入操作时，导出前会先尝试自动重打
- 选 YRP3D 时，游戏目录或 MDPro3 目录里要有 MDPro3

### 选择回放格式（支持上帝视角、我方视角、观战视角）

点「导出对局回放」后先选

![image-20261031215833962](../images/image-20261031215833962.png)

![image-20261031220748552](../images/image-20261031220748552.png)

| 选项                     | 文件                  | 观看方式                  | 手牌                       |
| ------------------------ | --------------------- | ------------------------- | -------------------------- |
| YRP（ygopro / EDOPro）   | `replay/<名称>.yrp`   | ygopro、EDOPro 的录像回放 | 双方手牌可见               |
| YRP3D · 回放（我方视角） | `replay/<名称>.yrp3d` | 只能在 MDPro3 观看        | 我方手牌可见，对方显示卡背 |
| YRP3D · 观战             | `replay/<名称>.yrp3d` | 只能在 MDPro3 观看        | 双方手牌都显示为卡背       |

YRP3D 需要 MDPro3 主目录，如果没有设置，导出时会提醒

也可以手动提前设置

![image-20261031220414927](../images/image-20261031220414927.png)

### 两种回放有什么不同

|              | `.yrp`                                      | `.yrp3d`                                       |
| ------------ | ------------------------------------------- | ---------------------------------------------- |
| 内容         | 操作应答、随机种子和开局数据。1v1 的开局盘面由 Lua 还原，2v2 标准的卡组数据写在回放内 | 整场对局的消息流，包含开局盘面和手牌视角 |
| 播放方式     | 客户端用 ocgcore 重跑，遇提问就取一条应答   | 客户端逐条播放，不跑核心                       |
| Lua 文件     | 1v1 需保留同名 `single/<名称>.lua`          | MDPro3 可直接播放单个 `.yrp3d` 文件。1v1 手动随机时，导出会同时生成配套 Lua |
| 能用的客户端 | ygopro、EDOPro                              | 只有 MDPro3                                    |

YRP3D 会记录连锁结算和阶段切换时的场上怪兽攻守，播放到这些时点时会更新显示。

### 起始抽牌

导出的 YRP 和 YRP3D 会在第 1 回合开始前播放起始抽牌。1v1 会按开局手牌的张数和顺序抽出这些卡，开局手牌为空的一方会跳过这段。YRP3D 仍按导出时选择的视角显示手牌。

### YRP 导出校验

导出 1v1 YRP 时，编辑器会用配套 Lua 重演已记录的应答。若引擎拒绝应答或回放提前结束，导出结果会提示「回放无法复现」。校验中途遇到错误时，会提示「回放校验未完成」。提示中会列出已读取的应答数和原因。

#### 本项目的`.yrp`文件，MDPro3读取不了

MDPro3 也能播**普通** `.yrp`（ygopro等保存的，联机对战等的回放），但它**播不了本项目导出的 `.yrp`**：本项目导出的是单模式回放，MDPro3 不认这个标志

#### 回放文件依赖说明

- **1v1 YRP**。换电脑播放时，把 `replay/<名称>.yrp` 和 `single/<名称>.lua` 一起拷到游戏目录
- **2v2 标准 YRP**。卡组数据在回放内，拷贝 `replay/<名称>.yrp` 即可
- **YRP3D**。在 MDPro3 中观看时，拷贝 `replay/<名称>.yrp3d` 即可。若 1v1 对局使用了手动随机，导出时还会生成 `single/<名称>.lua`，供内嵌 YRP 重演时使用

### 回放控制

- **播放/暂停**：底部播放键，或空格
- **上一步/下一步**：左右箭头，或 `←` / `→`
- **速度**：0.5×、1×、1.5×、2×、3×
- **回到开头**：旋转箭头
- **退出回放**：回到导入前的工程
- **编辑**：从当前回放步骤转成可编辑工程

![image-20261026144717144](../images/image-20261026144717144.png)

### 编辑回放

点“编辑”：

1. 以当前回放步骤为分叉点
2. 把该步之前的步骤保留
3. 把当前台面转成编辑器格式
4. 退出回放，进入可编辑状态
5. 标题会变成“A vs B”形式

之后的步骤不会保留
